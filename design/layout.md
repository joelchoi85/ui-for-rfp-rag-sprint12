# 화면 구조

두 화면뿐이다. `/` 에서 공고를 고르고, `/notice/[id]` 에서 그 공고에 묻는다.
이 문서는 그 두 화면의 뼈대와, 각 화면이 가질 수 있는 상태를 정한다.

---

## 0. 이 제품이 파는 것

검색 결과가 아니라 **판단 근거**다. 입찰 담당자는 "예산 4억"이라는 문장을 안 믿는다.
"공고문 몇 쪽 어디에 그렇게 쓰여 있는가"를 믿는다. 화면 설계는 전부 여기서 갈린다.

### 원칙 셋

**1. 근거는 장식이 아니라 구조다.**
답변 안의 `[1]` 은 각주가 아니라 조작 가능한 요소다. 짚으면 우측 출처 패널의 해당
카드가 켜지고, 원문 발췌가 보인다. 이 연결이 빠지면 제품이 아니라 데모다.
그래서 출처에는 브랜드 색(violet)이 아니라 **전용 색(sky)** 을 줬다 —
"내가 누른 것"과 "근거"는 다른 종류의 파랑이어야 한다.

**2. 순위를 믿게 만들지 않는다.**
검색은 리랭커를 뺐다. Top10 적중 0.839, Top1 은 0.565다. 목록 안에는 있지만
1등이 정답이란 뜻은 아니다. 그래서 화면에는 **순위 번호(1위·2위)를 절대 쓰지 않는다.**
대신 눈금 없는 관련도 막대를 카드 구석에 작게 둔다. 사람이 목록을 훑어 고르게
만드는 게 이 화면의 일이다.

**3. 3~5초를 숨기지 않고 설명한다.**
스트리밍이 백엔드에 없다. 스피너 하나로 4초를 버티면 고장 난 걸로 보인다.
어느 단계에 있는지 말한다 — 검색 → 후보 추림 → 답변 생성. 리랭킹 구간이 제일 길다.

## 1. 앱 셸

```
┌──────────────────────────────────────────────────────────────┐
│  [logo] NLP of Legend            gpt-5-mini ▾   ☾   ← 56px  │  Topbar (sticky)
├──────────────────────────────────────────────────────────────┤
│                                                              │
│                     content (max 1240px)                     │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

- 사이드 내비게이션을 안 만들었다. 갈 곳이 두 개뿐인데 레일을 두면 빈칸이 생긴다.
  화면이 셋 이상 되면 그때 만든다.
- Topbar 는 `position: sticky`. 모델 선택은 `GET /models` 로 채우고, 고른 값은
  두 화면이 공유한다(질문할 때 `model` 로 넘어간다).
- 다크 토글은 `:root[data-theme]` 만 바꾼다. 시스템 설정이 기본값이다.

## 2. `/` — 공고 검색

### 레이아웃

```
┌──────────────────────────────────────────────────────────────┐
│  Topbar                                                      │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│    어떤 사업을 찾으세요?                            32px     │
│    나라장터 공고를 자연어로 찾습니다                 15px muted│
│                                                              │
│    ┌────────────────────────────────────────────────┐ 56px   │
│    │ 🔍  클라우드 전환 사업                  [ 찾기 ]│        │  SearchBar
│    └────────────────────────────────────────────────┘        │
│    ⌗ 장애인 접근성 개선   ⌗ 이러닝 시스템 운영   ⌗ 관제 시스템│  예시 칩
│                                                              │
│    ─────────────────────────────────────────────── 24px gap  │
│    [ 예산 ▾ ]  [ 발주기관 ▾ ]  [ 마감일 이후 ▾ ]     초기화   │  FilterBar

│                                                              │
│    ┌─ NoticeCard ─────────────────────────────────────────┐  │
│    │ 국민연금공단                          [D-12] [진행중] │  │
│    │ 2024년 이러닝시스템 운영 용역                  17px/600│  │
│    │ 4억 2,000만원 · 2024-04-15 마감 · 발췌 37건    13px    │  │
│    │ …클라우드 기반 학습관리시스템으로 전환하여 운영…  muted│  │
│    │ 관련도 ▬▬▬▬▬▬░░░                      질문하기 →     │  │
```

### 규칙

| 항목 | 정한 것 | 왜 |
|---|---|---|
| 카드 폭 | 단일 열, 최대 880px | 제목이 길다. 2열로 깨면 두 줄이 세 줄 된다 |
| 제목 | 2줄에서 자른다(`line-clamp: 2`) | 공고명이 40자를 넘는 게 흔하다 |
| 예산 | 억/만원 한글 단위 + 숫자는 `font-variant-numeric: tabular-nums` | 자릿수 비교가 세로로 맞아야 한다 |
| 마감 | D-day 뱃지. D-7 이하 warning, 지났으면 danger + 카드 흐리게 | 마감이 지난 공고는 목록에 남되 클릭 가능해야 한다(참고용) |
| 관련도 | 막대만. 숫자·순위 없음 | 원칙 2 |
| 발췌 | 1줄, 질의어 하이라이트 | 왜 이게 걸렸는지 한눈에 |
| 필터 | 예산·기관·마감일만 | 백엔드가 메타데이터로 거르는 항목과 정확히 일치한다. 없는 필터를 화면에 두지 않는다 |

### 필터 → API 매핑

```
예산 슬라이더 최소   → min_budget   (원 단위 정수)
예산 슬라이더 최대   → max_budget
발주기관 입력       → agency       (부분 일치)
마감일 이후         → closes_after ("2024-04-01")
결과 수             → top_n        (기본 10)
```

### 상태

| 상태 | 화면 |
|---|---|
| idle (첫 진입) | 검색창 + 예시 칩 3개. 결과 영역 없음. 빈 카드 자리를 만들지 않는다 |
| loading | NoticeCard 골격 5장. 스피너 대신 스켈레톤 — 0.7초라 짧다 |
| success | 결과 메타 + 카드 n장 |
| empty | "조건에 맞는 공고가 없습니다" + 필터 완화 제안(예산 하한을 내려보세요) + [필터 초기화] |
| error | 카드 자리에 인라인 오류. 토스트 금지 — 재시도 버튼이 같이 있어야 한다 |

## 3. `/notice/[id]` — 질의응답

### 레이아웃 (≥1024px)

```
┌──────────────────────────────────────────────────────────────┐
│ ← 목록 │ 2024년 이러닝시스템 운영 용역        gpt-5-mini ▾   │  Topbar (제목 치환)
├──────────────────────────────────────────────────────────────┤
│  국민연금공단 · 4억 2,000만원 · 2024-04-15 마감 · D-12       │  NoticeBand
├────────────────────────────────────┬─────────────────────────┤
│                                    │  출처 3건        280px  │
│  Q. 이 사업의 배정예산은?          │                         │
│                                    │  ┌ [1] ─────────────┐  │
│  ┌────────────────────────────┐    │  │ 국민연금공단      │  │
│  │ 배정예산은 4억 2,000만원   │    │  │ 2024년 이러닝…    │  │
│  │ 입니다 [1]. 부가세 포함이며│    │  │ ...20240330003-0  │  │
│  │ 계약 시 조정될 수 있습니다 │    │  │ "…배정예산 금     │  │
│  │ [2].                       │    │  │  420,000,000원…"  │  │
│  └────────────────────────────┘    │  └───────────────────┘  │
│  gpt-5-mini · 3.4초 · 1,240 토큰   │  ┌ [2] ─────────────┐  │
│                                    │  │ …                 │  │
│  ─────────────────────────────     │  └───────────────────┘  │
│                                    │                         │
│  ┌ 질문 ──────────────────────┐    │                         │
│  │ 이 공고에 대해 물어보세요…│▸│    │                         │
│  └────────────────────────────┘    │                         │
│  ⌗ 제출 서류는?  ⌗ 참가 자격은?    │                         │
└────────────────────────────────────┴─────────────────────────┘
```

- 본문 폭은 `--answer-max-width: 68ch`. 한글 기준 한 줄 40~45자다. 그 이상은 눈이 줄을 놓친다.
- 대화는 위에서 아래로 쌓인다. 새 질문은 아래에 붙고 스크롤이 따라간다.
- 출처 패널은 **가장 최근 답변의 출처**를 보여준다. 이전 턴의 출처는 그 답변 블록을
  클릭하면 다시 올라온다.

### 인용 연결 — 이 화면의 핵심

```
답변 텍스트의 "[1]"  →  CitationPill 로 파싱
   hover  : 해당 SourceCard 에 --color-cite-active 배경, 스크롤 이동
   click  : 카드 펼침(발췌 전문), pill 에 aria-current
   출처 카드 hover → 답변 속 같은 번호 pill 이 같이 켜진다 (양방향)
```

파싱 규칙: `/\[(\d+)\]/g` 로 잡고 `sources[n]` 에 맞춘다.
**`sources` 에 없는 번호는 pill 로 만들지 않는다** — 모델이 [4] 를 지어내도
클릭했을 때 빈 곳으로 데려가면 안 된다. 그냥 텍스트로 둔다.

### 진행 단계 (답변 대기 3~5초)

```
● 관련 문단 검색       완료 0.4초
● 후보 80건 다시 채점  진행중 ▁▃▅        ← 여기가 제일 길다
○ 답변 생성            대기
```

단계는 실제 백엔드 이벤트가 아니라 **시간 기반 추정**이다(스트리밍 없음).
그래서 "완료 0.4초" 같은 정확한 숫자를 지어내지 말고, 완료 표시만 한다.
응답이 오면 실제 `latency_sec` 로 갈아 끼운다.

### 상태

| 상태 | 화면 |
|---|---|
| idle | 공고 요약 밴드 + 추천 질문 칩 4개. 빈 대화 영역 |
| asking | ProgressSteps + 답변 자리 스켈레톤 3줄 |
| answered | 답변 + 인용 pill + 우측 출처 + 메타(모델·소요·토큰) |
| `ok: false` | **답변 블록 자리에** danger 톤 인라인 카드. `error` 문자열 그대로 + [다시 시도]. 상태코드는 200 이라 네트워크 오류와 구별해서 표시한다 |
| 네트워크 실패 | 같은 자리, 다른 문구("백엔드에 닿지 못했습니다 — :8088 이 떠 있나요?") |
| 출처 0건 | 답변은 보여주되 "이 답변에는 근거 문단이 없습니다" 경고 배너. 근거 없는 답을 조용히 내보내지 않는다 |

## 4. 반응형

| 폭 | 검색 화면 | 질의응답 화면 |
|---|---|---|
| ≥1280 | 중앙 880px | 본문 + 출처 280px 고정 |
| 1024~1279 | 중앙 880px | 본문 + 출처 240px |
| 768~1023 | 좌우 여백 24px | 출처가 답변 **아래** 아코디언으로 내려간다 |
| <768 | 카드 전폭, 필터는 하단 시트 | 출처는 pill 탭 시 하단 시트로 뜬다 |

모바일에서도 인용 연결은 살린다. 출처가 접히더라도 pill 을 누르면 열려야 한다.

## 5. 접근성

- 포커스 링은 `--focus-ring-*` 하나로 통일. `outline: none` 만 쓰고 링을 안 그리는 건 금지.
- CitationPill 은 `<button>`. `aria-label="출처 1 국민연금공단"`.
- 답변 영역 `aria-live="polite"` — 생성이 끝나면 스크린리더가 읽는다. 단계 표시는 `aria-live="off"`(시끄럽다).
- 관련도 막대는 색만으로 뜻을 전하지 않는다 — `title` 과 `aria-valuenow` 를 준다.
- 대비는 실측했다. 라이트·다크 양쪽에서 12쌍 전부 AA(4.5:1) 통과 — 최저가 경고 뱃지 4.84:1.
  처음엔 상태색을 `-600` 으로 잡았다가 걸렸다. `emerald-600 / emerald-50` 이 3.58:1,
  `amber-600 / amber-50` 이 3.07:1 이었다. **연한 배경에 같은 계열 -600 을 얹으면 거의 항상 떨어진다** —
  전부 `-700` 으로 내렸고, 다크에서는 반대로 `-300` 으로 올렸다.
- `slate-400`(`--color-text-subtle`)은 **비활성·장식에만** 쓴다(3.4:1 — 본문에 쓰면 떨어진다).
- 채움색과 글자색은 다른 토큰이다. `--color-primary` 는 버튼 배경, `--color-text-link` 와
  `--color-primary-subtle-fg` 는 글자다. 하나로 합치면 다크에서 반드시 한쪽이 깨진다.

## 6. 안 만든 것 (그리고 왜)

| 없는 것 | 이유 |
|---|---|
| 로그인 | 고객사가 하나다. 둘이 되면 그때 인증부터 |
| 문서 업로드 | 인덱스는 배치로 만든다. 화면에서 올리면 인덱싱 큐가 필요해진다 |
| 대화 저장 | 서버에 저장할 곳이 없다. 새로고침하면 사라진다 — 화면에 그렇게 적어둔다 |
| 원문 뷰어 | NDA 문서를 브라우저로 내보내는 결정이 먼저다 |
| 시나리오 A/B 선택 | 인프라 선택이지 고객의 선택이 아니다 |
